Welcome everyone. This session will walk through our plan to build the NextGen Test Automation framework from July 2026 to March 2027. We will cover what we are building, why, how the team is structured, and what milestones we will hit each phase.

The Problem We Are Solving

Today's Pain Points

  • Test automation requires coding expertise
  • Locators break after every UI change — manual fixing
  • Separate tools for Web, Desktop, API, DB — fragmented
  • Test case authoring is slow and expensive
  • No industry-specific intelligence out-of-the-box
  • AI features in existing tools are bolt-on, not core

Our Vision

  • Zero code required — anyone can automate
  • AI auto-generates test cases from a walk-through
  • Self-healing locators using vision AI
  • One platform for all test types
  • Industry templates out-of-the-box
  • Python-native, open ecosystem
The core problem we are addressing is the high barrier to entry for test automation and the constant maintenance burden. Our tool democratises testing.

🏭 Industry Intelligence

These four pillars are what make our tool genuinely next-generation. Competitors have pieces of this; we are combining all four in a single Python-native platform.

Risks & Mitigations

RiskSeverityMitigation
LLM API cost & reliability High Support local LLaMA / Ollama as free fallback
Desktop automation fragility across OS High Start Windows-only; add Linux/macOS in Phase 3
Self-healing false positives Medium Human approval panel before any auto-apply
Scope creep Medium Strict phase gates; mobile-native deferred to v2
Team bandwidth & coordination Medium Weekly sync, shared backlog, clear ownership
Open-source licensing conflicts Low License audit at Phase 0 completion
The two highest risks are LLM costs and desktop automation. Both have concrete mitigations planned. Self-healing accuracy is managed through human oversight rather than blind automation.
